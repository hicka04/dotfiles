# Planning

以下の順番に従って実行プランを立ててください

* 依頼内容に関連するコードを読んで、現状の仕様を理解してください
    * 不明点があれば、必要に応じて質問してください
        * 質問は `AskUserQuestion` を使ってください
* 実装方法を検討してください
    * 実装方法が複数ある場合は、それぞれのメリット/デメリットを提示して、どの選択肢を取るか質問してください
        * このとき、提示された選択肢以外の方法を提案することがありますので、私の提案も含めて再度メリット/デメリットをまとめ直してください
* 実装方法が決まったら、ステップを分割してタスクを作成してください
    * **1タスク = 1コミット** になるよう分割してください
    * 1つのステップで、複数のファイルに対して同じような操作をする場合は、それらを個別の小タスクとして分割してください
    * コンポーネントの「作成」と、それを「使用する」変更は別タスクにしてください
* 動作確認方法を私に質問してください
* 実行プランは、私との会話のコンテキストをできるだけ排除し、初めて読む人に向けてわかりやすくなることを意識してください

これらが終わるまでは**実装を開始しないでください**

# Coding

以下の手順に従って、立てた実行プランに沿った実装を行ってください

* タスクごとに作業をしてください
* コード内のコメントは必要最低限のみ残してください
    * ドキュメントコメント
        * メソッド名や引数名からではわからない、利用側に伝えたい使い方のポイントのみ記述してください
    * インラインコメント
        * なぜこの実装にしたのか・なぜ他の実装を採用しなかったのか、経緯のみ記述してください
* 1つのタスクが終わるごとに以下を実施してください
    * 動作確認
    * コミット
        * コミットメッセージは英語で書いてください
        * Conventional Commits形式（`feat:` / `fix:` / `refactor:` など）は使わない
        * 動詞の命令文で始める（Add / Create / Remove / Replace / Move / Use / Set / Apply / Show / Fix / Refactor など）
        * ビルドが通る状態を保ちながら小さくコミットを積む（未実装部分は TODO コメントで後回しにするなど）
        * ビルドエラーが生じた場合は amend せず、新しいコミット（`Fix build fail` など）として積む
        * コミット時の Co-authored には `Claude Code` が作業したことがわかるようにしてください
